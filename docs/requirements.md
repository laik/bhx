# 需求文档 v0.2

> 本版相对 v0.1 的核心变化：从「浏览器游戏控制工具」调整为「通用 AI Browser Harness」。
> 游戏降级为 Phase 5 的负载之一，不再是产品的验收依据。

## 1. 定义

**Browser Harness 是给 AI Agent 用的浏览器执行基础设施。**

它提供三件事：

1. **可观察**：把真实浏览器状态压缩成 Agent 和模型能吃的结构化数据（元素索引、页面状态、截图）。
2. **可操作**：把「点击导出按钮」这类意图，稳定地翻译成 CDP 输入事件，并处理 iframe、Shadow DOM、跨域、DPR、滚动等脏活。
3. **可验证与可恢复**：每次动作有成功条件，失败有上下文，中断有清理，重启可从检查点继续。

它**不是**一个 Agent，**不**拥有用户意图，**不**决定要不要做这件事。

## 2. 非目标

明确不做，防止范围蔓延：

| 非目标 | 原因 |
|---|---|
| 每步都调用大模型的 Browser Agent | 成本与延迟不可接受，且不稳定；Harness 要求模型不在关键路径上 |
| Playwright 的瘦封装 | 那样只得到一个 Python/Node 库的壳，拿不到 CDP 层面的控制权与延迟 |
| 通用爬虫 / 大规模采集 | 那是另一类系统（代理池、调度、反爬），本项目的单位是「一个任务」 |
| 视觉模型的训练或托管 | Harness 只做适配与调度 |
| 替代 RPA 的图形化编排 UI | 第一版只提供协议与 API |
| 突破网站的反自动化防护 | 不以规避检测为目标；需要隔离环境时用独立 profile / 远端浏览器 |

## 3. 能力模型

四类能力，共用一套浏览器基础设施，但**不强制**走同一条操作路径。

| 能力 | 典型任务 | 主路径 | 模型参与度 |
|---|---|---|---|
| 网页理解 | 读结构、提信息、找元素 | Accessibility Tree + DOM | 低（规则可解决大部分） |
| 工作自动化 | 填表、后台管理、跨页流程、数据整理、导出 | DOM Executor + 任务引擎 | 每任务 0–2 次（仅规划与升级） |
| 视觉操作 | Canvas、WebGL、无语义控件、按布局定位 | Vision Executor + 坐标控制 | 每个视觉步骤 1 次 |
| 实时交互 | 连续按键/拖拽、动态页面、需要反馈闭环 | Interactive Controller | 低频（只下发/修正策略） |

关键约束：**能力之间可以组合**。一个任务里可以「DOM 定位按钮 → 截图确认弹窗 → 键盘完成输入」。

## 4. 设计原则

1. **语义优先，坐标为后备。** 能用 role+name 就不用 CSS，能用 CSS 就不用坐标。坐标是最后手段，且必须附带重定位描述。
2. **慢思考在 Agent，快执行在 Harness。** 规划可以慢、可以贵；执行必须零模型调用。
3. **每个动作都可验证。** 没有成功条件的动作，视为「未验证」，在报告里单列。
4. **可取消、可中断、可恢复。** 取消要在 200ms 内生效，且不得残留按下的键或鼠标按键。
5. **副作用分级。** 只读 / 可逆 / 不可逆三级；不可逆动作默认需要显式批准。
6. **观察是有预算的。** 默认只序列化可交互元素与前 N 个可见文本块，并支持动作后差分，避免把整页 HTML 塞给模型。
7. **默认确定性。** 不做拟人化抖动；需要时显式开启。可复现优先于「像人」。

## 5. 使用者与集成方式

| 使用者 | 接入方式 | 典型用法 |
|---|---|---|
| Claude Code / Pi / Qwen 等 Agent | MCP | `task.start(goal=..., mode="auto")` 后订阅事件 |
| 脚本 / CI | REST + WebSocket | 跑验收套件、定时任务 |
| 人 | CLI (`bhx`) | 调试、录屏、复现失败任务 |

同一个 Harness 进程可服务多个调用方；会话与浏览器上下文按任务隔离。

## 6. 安全与权限（v0.1 缺失，本版补上）

Harness 持有真实登录态，必须比普通脚本更保守：

- **Profile 隔离**：每个任务可指定独立 `user_data_dir`；默认不共享 cookie 给不同调用方。
- **域名白名单**：任务可声明 `allowed_hosts`，越界导航直接失败而非弹窗询问。
- **不可逆动作审批**：提交订单、删除、发送消息、付款等默认拦截，返回 `waiting_approval` 事件，由调用方决定继续或取消。
- **凭据不落日志**：输入框中的密码类内容在 trace、事件、截图中一律脱敏；截图可配置对 `[type=password]` 区域打码。
- **下载沙箱**：下载落到任务专属目录，文件名净化，大小上限可配。
- **JS 求值分级**：`evaluate` 默认在 isolated world 执行；main world 需显式声明。
- **人工接管**：登录墙 / MFA / 验证码不自动破解。任务进入 `waiting_human`，用户手动完成后 `task.resume`。

## 7. 验收标准

不再用「点中一个按钮」作为完成标准。验收由三组套件构成，全部跑在**本地固定测试场**上（不依赖公网，避免站点改版导致假红）。

测试场 `testkit/sites/`：

| 站点 | 用途 |
|---|---|
| `admin/` | 登录、订单列表、多条件筛选、分页、导出 CSV、随机 cookie 弹窗 |
| `form/` | 多步表单、字段校验错误、文件上传、条件显示字段 |
| `canvas/` | 纯 canvas 渲染的图表与控件，无 DOM 语义 |
| `game/` | 2D canvas 小游戏，键盘 + 鼠标连续操作 |
| `chaos/` | 可注入延迟、元素位移、A/B 布局、请求失败、偶发弹窗 |

### A. 工作自动化（必须有）

1. 导航并提取页面内容（结构化输出，字段正确率 100%）。
2. 填写多步表单并验证服务端接受。
3. 条件查询并导出文件（文件存在、行数正确、编码正确）。
4. 跨页面完成 5 步以上流程。
5. 处理中途弹窗与接口错误后仍完成主流程。

### B. 视觉操作

1. 从截图中定位目标控件。
2. 定位无可靠语义标签的控件（canvas 内按钮）。
3. 完成拖拽（起点/终点正确，落点误差 ≤ 4px）。
4. 判断操作是否成功（用状态而非截图相似度）。
5. 页面布局变化后重新识别目标。

### C. 连续交互

1. 连续键盘输入（按下/释放配对，无粘键）。
2. 带时间限制的鼠标动作。
3. 观察状态并调整动作（简单闭环）。
4. 超时后安全停止并释放全部输入。
5. 浏览器异常时清理输入状态并标记任务失败。

### 指标（每次运行都记录）

| 指标 | 目标 |
|---|---|
| 任务成功率 | A 组 5/5；B 组 ≥ 4/5；C 组 5/5（阶段性中间目标见 roadmap） |
| 每任务模型调用次数 | A 组 ≤ 2；C 组 ≤ 1（仅策略生成） |
| 无效动作率（未引起预期状态变化） | < 5% |
| 单动作 p95 延迟（本地） | < 50ms |
| 观察 p95 延迟（1280×800） | < 150ms |
| 取消生效延迟 | < 200ms |
| 故障注入后恢复率 | ≥ 80% |
| 中止后残留按键 | 0 |

## 8. 失败的定义

以下任一情况即判定该版本不达标，不因「大部分情况能用」而豁免：

- 需要在每个动作间等待模型返回才能继续。
- 元素定位依赖固定坐标且无后备策略。
- 任务失败后无法说明失败原因（缺少页面快照、元素候选、最后一次动作）。
- 取消后仍持续发送输入。
- 同一任务重复执行会产生不可逆副作用（重复提交）。
